# Документация по сайту табеля

## Назначение

Сайт нужен для учета рабочего времени сотрудников. Сотрудник запускает рабочий день, при необходимости ставит одну паузу на обед и завершает работу. Администратор видит все записи, может исправить время и удалить ошибочные строки.

## Роли

В системе две роли:

- Сотрудник - регистрируется, входит в систему и ведет свой рабочий день.
- Администратор - входит через отдельную кнопку и управляет строками табеля.

## Главная страница

На главной странице есть три кнопки:

- `Регистрация`
- `Вход`
- `Администратор`

На внутренних страницах есть кнопка `Домашняя страница`, которая возвращает пользователя назад на главную.

## Регистрация сотрудника

Поля регистрации:

- `Имя`
- `Email`
- `Пароль`

Правила:

- Имя обязательно.
- Email должен быть в формате почты, например `user@mail.ru`.
- Email должен быть уникальным. Один email нельзя зарегистрировать два раза.
- Пароль должен быть минимум 6 символов.

Если регистрация прошла успешно, сайт показывает сообщение об успешной регистрации. После этого сотрудник возвращается на главную страницу и нажимает `Вход`.

Если email уже зарегистрирован, нужно не регистрироваться снова, а войти через страницу `Вход`.

## Вход сотрудника

Поля входа:

- `Email`
- `Пароль`

После успешного входа открывается страница `Рабочий день`.

## Работа с табелем сотрудника

1. Сотрудник вводит название проекта.
2. Нажимает `Начать работу`.
3. Сайт запускает учет времени.
4. Если нужен обед, сотрудник нажимает `Пауза на обед`.
5. После обеда сотрудник нажимает `Продолжить работу`.
6. В конце дня сотрудник может написать комментарий.
7. Нажимает `Закончить работу`.
8. Запись появляется в таблице `Мои записи`.
9. После работы сотрудник нажимает `Выход`.

Ограничения:

- Одновременно может быть только одна активная работа.
- За одну рабочую смену можно поставить только одну паузу на обед.
- Время обеда вычитается из итогового рабочего времени.
- Если сотрудник завершает работу во время активной паузы, обед автоматически закрывается тем же временем.

## Вход администратора

На главной странице нужно нажать `Администратор`.

Данные по умолчанию:

- Имя: `admin`
- Пароль: `555555`

На сервере пароль можно заменить через переменную окружения `ADMIN_PASSWORD`.

## Админ-панель

Администратор видит таблицу рабочих смен:

- Имя сотрудника
- Дата
- Проект
- Начало работы
- Начало обеда
- Конец обеда
- Окончание работы
- Итоговое время
- Комментарий
- Действия

Администратор может:

- изменить проект;
- изменить начало работы;
- изменить начало или конец обеда;
- поставить окончание работы, если сотрудник забыл завершить смену;
- изменить комментарий;
- сохранить строку;
- удалить ошибочную строку.

Если таблица шире экрана, она прокручивается горизонтально внутри блока таблицы.

## Проверка перед запуском на сервер

1. Запустить приложение:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

2. Проверить backend:

```bash
curl http://127.0.0.1/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

3. Открыть сайт:

```text
http://127.0.0.1/
```

4. Проверить сценарий сотрудника:

- зарегистрировать нового сотрудника;
- войти;
- ввести проект;
- нажать `Начать работу`;
- нажать `Пауза на обед`;
- нажать `Продолжить работу`;
- написать комментарий;
- нажать `Закончить работу`;
- убедиться, что запись появилась в `Мои записи`;
- нажать `Выход`.

5. Проверить сценарий администратора:

- открыть главную страницу;
- нажать `Администратор`;
- войти как `admin` / `555555`;
- найти строку сотрудника;
- изменить окончание работы или комментарий;
- нажать `Сохранить`;
- при необходимости удалить тестовую строку;
- нажать `Выход`.

Если эти шаги проходят, локально сайт готов к переносу на сервер.

## Переменные окружения

Файл `.env.example` содержит пример:

```env
POSTGRES_USER=tracker
POSTGRES_PASSWORD=change_this_database_password
POSTGRES_DB=tracker
SECRET_KEY=change_this_to_a_long_random_secret_key
ADMIN_USERNAME=admin
ADMIN_PASSWORD=555555
```

Что важно заменить на сервере:

- `POSTGRES_PASSWORD` - пароль базы данных.
- `SECRET_KEY` - секретный ключ для JWT-токенов.
- `ADMIN_PASSWORD` - пароль администратора.

Секретный ключ можно сгенерировать так:

```bash
openssl rand -hex 32
```

## Типовые проблемы

### Сайт не открывается

Проверить контейнеры:

```bash
docker compose -f docker-compose.prod.yml ps
```

Проверить логи:

```bash
docker compose -f docker-compose.prod.yml logs -f backend
docker compose -f docker-compose.prod.yml logs -f frontend
```

### Ошибка `Email already registered`

Такой email уже зарегистрирован. Нужно перейти на страницу `Вход` и войти с этой почтой.

### Администратор не входит

Проверить:

- имя должно быть `admin`, если не меняли `ADMIN_USERNAME`;
- пароль должен совпадать с `ADMIN_PASSWORD`;
- после изменения `.env` нужно перезапустить контейнеры:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

### Данные пропали после перезапуска

Обычный перезапуск не удаляет данные. Данные PostgreSQL хранятся в Docker volume `pg_data`.

Данные можно потерять, если удалить volume командой вида:

```bash
docker compose -f docker-compose.prod.yml down -v
```

Эту команду нельзя использовать на рабочем сервере без полной уверенности.
